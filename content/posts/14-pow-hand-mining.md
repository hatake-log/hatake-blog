[前回の記事で](/posts/mining-basics/)、マイニングとは「帳簿の次のページを書く係を決める、計算が要るくじ引き」と表しました。ただ、言葉だけだといまいちスッキリしません。

そこで、ターミナルで「小さいマイニング」をやってみました。使うのは`sha256sum`という関数です。

## ハッシュ値＝指紋のように唯一無二

`sha256sum`とはLinuxコマンドで、ブロックチェーンでもこの仲間がマイニングに使われています。マイニングにおいて`sha256sum`が何をするかというと、「何らかの値を受け取って、64桁の英数字（16進数）を1つ出す」という計算を行います。

実際に`sha256sum`を使ってみます。”hatake”という文字列を`sha256sum`に渡すと・・・

```bash
$ echo -n "hatake" | sha256sum
f4f04fcdce45e8fe289499c9d762749c8ef422808e7079031c44e6d638f18e20  -
```

f4f04・・・・という６４桁の英数字が返ってきました。

次は、値をすこーしだけ変えて、"hatake!"を渡してみます。

```bash
$ echo -n "hatake!" | sha256sum
21823b187065dbf35ecf1cff7ae355269b5213139e3738c63e05eeddb0b04713  -
```

21823b・・・になりました。先ほどと全く違う別物の文字列ですが、６４桁の英数字です。

もう一度、最初の”hatake”でやってみましょう。

```bash
$ echo -n "hatake" | sha256sum
f4f04fcdce45e8fe289499c9d762749c8ef422808e7079031c44e6d638f18e20  -
```

f4f04・・・・最初と同じ内容が出てきました。

この６４桁の英数字には以下の特徴があります。

- 元の値が少しでも違えば、出力値が被ることはない
- 出力値から、元の値は推測できない
- 意図した出力値を出すことはできない

まとめると、`sha256sum`はどんなデータを入れても、64桁の英数字（16進数）が1つ出てくる計算で、出力値が被ることはない。つまり、**データの指紋**のような感じです。

指紋なので、唯一無二。他のどんな値を使っても同じハッシュ値を作ることはできません。そして、マイニングの**くじ引き**にはこのハッシュ関数が道具として使われています。

## 「先頭がゼロで始まるハッシュ値」を探す

次に、くじ引きのルールを決めます。「**ハッシュ値の先頭が`000`で始まっていたら、当たり！**」とします。

そして、ハッシュ関数に渡す元の値は何かというと、マイニングの場合は送金などのコインの手続きがまとまったデータです。

その元の値をハッシュ関数に渡して出てきたハッシュ値の先頭が、`000`で始まっていたらアタリです。

ただし、元の値をハッシュ関数にかけた結果がハズレだったら、そこで終わってしまいます。元の値とハッシュ値は１対１、何度計算しても同じハズレの結果です。

そこで使われるのが**ノンス**（nonce）と呼ばれる使い捨ての数字です。手続きがまとまったデータノンスをプラスすれば、元データが変わるのでハッシュ値も変わります。

つまり、ノンスを0、1、2、3……と変えながらハッシュ値がアタリになるまでひたすら計算をする。これがマイニング計算の中身のようです。地味だけど大変ですね・・・！


これを簡易なコードにしました。

取引データのまとまり："hatake"
ノンス：0スタート。1、2、3・・・と変えてゆく

「hatake0」「hatake1」「hatake2」……と指紋を取り続けて、先頭が`000`になったら止まる、というループです。実行結果です。

```bash
target="000"
n=0
while :; do
  h=$(printf 'hatake%d' "$n" | sha256sum | cut -c1-64)
  case "$h" in ${target}*) break;; esac
  n=$((n+1))
done
echo "nonce=$n hash=$h"
```


```
nonce=10328 hash=000f56303cb921cac78fee7ee9e6748fb69b56762405194fc733de3f487ce7b9
```

10,328回めで当たりました。13秒ほどです（遅いのはシェルで1回ずつコマンドを呼んでいるからで、本物のマイニングソフトなら同じ計算を1秒に何百万回も引きます）。

**これがマイニングです**。本物とは規模も細部も違いますが、やっていることの骨格は同じで、「指紋の先頭にゼロが並ぶノンスを、総当たりで探す」だけ。特別に賢い計算ではなくて、ただの根気です。

## 難易度の正体は、ゼロの桁数

面白いのは、当たりの条件のゼロを1桁増やしたり減らしたりしたときです。`target`を変えて何度か回してみました。

| 当たりの条件 | 見つかったノンス | 試行回数の期待値 | かかった時間 |
|---|---|---|---|
| `0`で始まる | 18 | 16回 | 一瞬 |
| `00`で始まる | 384 | 256回 | 0.5秒 |
| `000`で始まる | 10,328 | 4,096回 | 13秒 |
| `0000`で始まる | 12,129 | 65,536回 | 15秒 |

16進数（0〜9とa〜fの16種類）なので、1桁につき16通り。**ゼロを1桁増やすごとに、当たる確率は16分の1になります**。期待値の列がきれいに16倍ずつ増えているのはそのためです。

一方で、実際に見つかったノンスの列はきれいではありません。`000`は期待値の2.5倍かかって運が悪く、`0000`は期待値の5分の1で見つかって豪運でした。くじ引きなので毎回ブレます。本物のマイニングでも「計算力が大きいほど当たりやすい」のは確率の話で、小さな計算力でもたまたま当たることはある、というのがここで実感できました。

このゼロの桁数が、いわゆる**難易度**です。ビットコインの場合は「先頭のゼロの数」ではなく「指紋を数として見たときに、目標値より小さければ当たり」というもう少し細かい決め方をしていますが、考え方は同じです。目標値を下げるほど当たりにくくなります。

ここまで分かると、本物のチェーンがやっている**難易度調整**という仕組みも腑に落ちます。参加者が増えて当たりが早く出すぎるようになったら、ネットワークが「じゃあ次からはゼロ5つね」と条件を厳しくする。逆に減ったら緩める。それだけの話でした。ちなみにゼロ5つだと期待値は約100万回で、このシェルのループだと20分以上かかる計算です。

この難易度調整、実は[Moneroのテストネット](/posts/monero-testnet-mining/)で目撃していました。参加者が少なすぎて難易度がとても低く、私のミニPC1台がネットワークの半分近くを占めてしまい、数時間で51ブロックも当たったのです。掘り始めたあとに全体のハッシュレートがじわじわ上がっていったのも、今思えばこの調整が働いていたのでした。あのときは「なんだこれ」と思っていましたが、今なら理由が説明できます。

## 検証は一瞬、探すのは大変

もう1つ大事な性質があります。誰かが「ノンス10328で当たりました」と言ってきたら、それが本当かどうかは`sha256sum`を**1回**計算するだけで確かめられます。

```bash
$ echo -n "hatake10328" | sha256sum
000f56303cb921cac78fee7ee9e6748fb69b56762405194fc733de3f487ce7b9  -
```

探すのに1万回かかったものが、検証は1回で済む。

だからこそ、ネットワーク上の他の参加者は、当たった人の計算をやり直さなくても「たしかに当たりだ」と納得できて、そのページを帳簿に載せることに合意できます。この「探すのは大変・確かめるのは簡単」という非対称が、PoWの核心のようです。

## そもそも、なぜノンスが要るのか

ここは私が引っかかって、自分なりに答えを出した部分です。

指紋の先頭のゼロの数は、直接いじれません（指紋を狙って作れないから）。だとすると、指紋を変えるには**元のデータの側を変える**しかない。でも帳簿のページの中身は「AさんがBさんに1コイン送った」という取引の集まりで、それぞれに送り主の署名がついていますから、書き換えると署名が合わなくなってページごと無効になります。

そこで、ページの中身とは無関係に**自由に回してよいダイヤル**を1つ、ページに付けておく。それがノンスです。取引には一切触らず、このダイヤルだけを0、1、2……と回して指紋を取り直す。「くじを引き直す」とは、このダイヤルを1つ進めることでした。

## 本物との違い

やってみて分かった「骨格は同じ」の範囲と、本物との違いを整理しておきます。

- **ハッシュ関数**: ビットコインはSHA-256を2回重ねたもので、今回の`sha256sum`と同じ仲間です。MoneroのRandomXやCodablecashのアルゴリズムは別物で、GPUやASICでは速くならないようにわざと設計されていますが、「ノンスを変えて総当たり」という使い方は同じです
- **速度**: 今回のループは1秒に800回ほどしか引けていません。[Moneroのテストネット](/posts/monero-testnet-mining/)で同じミニPCを本物のマイニングソフトで動かしたときは、1秒に1,000回以上でした。RandomXはSHA-256よりずっと重い計算なのに、それでも本物のソフトのほうが速い。シェルのループがいかに遅いかが分かります
- **当たりの条件**: 上に書いたとおり、本物は先頭ゼロの数ではなく「目標値以下」で判定し、その目標値がネットワーク全体で自動調整されます
- **元データ**: 今回は「hatake」でしたが、本物は帳簿のページ（ブロック）の要約で、前のページの指紋も含まれています。だから1ページ書き換えると後ろのページの指紋が全部変わり、ブロック「チェーン」になっています

## まとめ

- くじ1回＝ハッシュ計算1回。「指紋の先頭にゼロが並ぶノンス」を総当たりで探すのがマイニング
- 難易度＝ゼロの桁数。1桁増えるごとに16倍大変になる
- 探すのは大変、確かめるのは一瞬。この非対称がPoWの核心
- ノンスは「取引に触らずに指紋を変えるための、自由に回してよいダイヤル」

同じことは、Linuxがあれば誰でも数分で試せます。マイニングがなんだかよく分からない方は、`sha256sum`に自分の名前を入れるところから、ぜひ。
